# Key Concepts

坐标系由原点和三条有方向的正交单位轴组成。点的坐标必须说明相对哪个坐标系。
本课沿用 [Stage 3 单杆几何](../examples/03_pd_control/single_joint.xml)：
关节原点位于世界 (0,0,0.5) m，杆沿自身 +x 方向长 0.4 m，绕 +z 轴旋转。
不改变模型或运行它；手算的 q=0、q=π/2 与仿真实验初值 0.3 rad 不同。

- W：固定世界坐标系。
- J：本课人为选定的关节处局部系，原点在铰链，轴随杆旋转；不是把所有 joint 都视为独立 MuJoCo body。
- E：选在杆端的末端坐标系，本例轴与 J 平行，原点位于 J 的 (0.4,0,0) m。
  这是教学中定义的坐标系，现有 XML 没有新增末端 body 或 site。

杆端点 P 在 J 中的坐标 p_J=(0.4,0,0) m，随刚性杆运动保持不变；
在 E 中坐标为零（它就是 E 原点）；在 W 中的位置可能随关节角改变。

```text
p_W = R_WJ * p_J + t_WJ
```

p_J、p_W 为同一点的 3×1 列向量，单位 m。
R_WJ 是 3×3 无量纲旋转矩阵，将 J 中表示的向量转换成 W 中表示；
三列依次是 J 的 x/y/z 单位轴在 W 中的坐标。
t_WJ 是 J 原点在 W 中的 3×1 位置，单位 m；必须与旋转后的向量在同一坐标系相加。
几何意义：先把从 J 原点指向 P 的箭头换成世界轴分量，再加上 J 原点的世界位置。
变换坐标表示本身不是执行物理运动。

q=0 时两系轴平行，R 为单位矩阵；p_W=(0.4,0,0)+(0,0,0.5)=(0.4,0,0.5) m。
绕 +z 正向旋转遵循右手定则：从 +z 一侧向原点看为逆时针，+90°=π/2 rad。
该角度下 J 的 +x 指向世界 +y，J 的 +y 指向世界 -x，+z 不变：

```text
R_WJ = [0 -1  0]
       [1  0  0]
       [0  0  1]
```

## S4.3：读取 UR5e 末端 site 位姿（已完成）

2026-09-28 用户选择本步。静态核对缓存 ur5e.xml 的 wrist_3_link：

```xml
<site name="attachment_site" pos="0 0.1 0" quat="-1 1 0 0"/>
```

pos 是相对所属 body 的局部位置（m），不是世界位置；quat 定义相对 body 的
局部朝向，本步不展开四元数。以此 site 作为模型末端参考，不等同于任意实际工具尖端。
和 S4.1 的人为 J/E 定义不同，此处读取模型实际存在的 site。

待读取字段与语义：

- model.site("attachment_site").id：按名称取得 site ID，整数，不是 joint ID。
- model.site_pos[site_id]：形状 (3,)，site 原点相对所属 body 的位置，m。
- data.site_xpos[site_id]：形状 (3,)，site 原点在世界系的位置，m。
- data.site_xmat[site_id]：形状 (9,)，按行存储的旋转矩阵；reshape(3,3) 后得到 R_WE。
  三列分别是 site 的 x/y/z 单位轴在世界中的方向，无量纲，不是三个欧拉角。
  NumPy reshape 只改变数组形状，不重新计算位姿；copy 用于保留快照。
- home 初始化后调用 mj_forward(model,data)，原地刷新派生量，返回 None、不推进时间。
  直接设置 qpos 后也需刷新，不能把旧缓存当成新位姿。

依据：[官方 mjData 字段](https://github.com/google-deepmind/mujoco/blob/main/include/mujoco/mjdata.h)、
[官方坐标与矩阵存储说明](https://mujoco.readthedocs.io/en/latest/programming/simulation.html)。

拟先读取 home 位姿，再只改一个关节 qpos 并 forward，对比局部位置、世界位姿与时间。
这是姿态设置和运动学计算，不模拟运动过程，不实现 IK 或控制器。
