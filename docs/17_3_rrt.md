## Problem → Why

上一课手动给出绕行waypoints。现在让程序自己探索配置空间，找到start→goal的几何path。
不重新实现碰撞检查，不做平滑、时间化、RRT-Connect或UR5e整合。

## Intuition → Core Concepts

从start长出一棵树：随机选一个目标，找到树中最近节点，朝目标迈一小步；
只有这一小段通过边检查才插入节点。靠近goal时检查最后连接，成功后沿parent回溯。
树像逐步探路的分叉路线，不是随机生成一整条路径后碰运气。
最近节点分配使拥有较大Voronoi区域的节点更容易被均匀样本选中，促使树探索。
算法来源：[LaValle 的RRT说明](https://www.lavalle.pl/rrt/about.html)。

本课采用single-tree geometric RRT + goal bias。朴素NumPy遍历nearest，避免额外数据结构。
保存`nodes_m`与`parents`两个并行数组，parent index就是连接关系；不保存复杂Node类。

## Mathematics：形状、单位、frame

沿用二维sphere-on-XY-slides：q∈[-1,1]² m，对应world xy；C-obstacle半径45 mm。

```text
q_target = goal（概率p），否则Uniform([-1,1]²)
i_near = argmin_i ||q_i-q_target||₂
v = q_target-q_near, d = ||v||₂
q_new = q_near + min(1, η/d) v          # d≈0则跳过重复点
若 sampled_edge_valid(q_near,q_new,h)：加入节点并记parent=i_near
若 ||goal-q_new||₂ ≤ η：检查q_new→goal，通过后追加goal
```

q/v shape `(2,)`，米；d/η/h是米，p无量纲。η默认0.15 m是树扩展长度上限；
h默认0.02 m是碰撞查询间距，两者用途不同。nearest用的metric与steer方向一致。
树边通常≤η；搜索前的start→goal直连测试可长于η，但仍检查完整边。

回溯：从goal index沿parent直到root的−1，把索引序列逆序。
路径长度 `sum ||q[i+1]-q[i]||₂`，单位m。本课找到首条可行路径就停止，不保证最短。

## Math-to-Code / APIs

`plan_rrt`顺序：参数检查→start/goal合法性→直连尝试→sample/nearest/steer/edge/parent循环→回溯。
`reconstruct`只负责沿parent取索引；`steer`显式保留距离和步长表达式。

复用本地`edge_checking.py`的model、bounds、configuration_report、check_edge。
其NumPy/MuJoCo/Matplotlib均是必需执行依赖，不需要OpenCV/Menagerie/Torch。
`MjModel`共享只读模型；`MjData(model)`创建live与独立query状态；
`mj_forward(model,data)`返回None并原地更新FK/contact/cache，不推进时间。
本课没有新MuJoCo API；详细输入/shape/frame见S14.2。对候选查询的qpos赋值不代表动态执行。

- 每轮随机尝试都计入attempts，包括重复点和被拒绝扩展。
- max_nodes包括root与额外goal节点；max_attempts另行限制反复失败而树不增长的情况。
- time_budget_s用perf_counter单调时钟，检查操作前后合作式停止；单次边查询不可中断，可能略超时。
  search wall包括端点查询/直连/搜索/返回构建，**不包括**编译、后验评分、复查、保存和绘图；不是硬实时deadline。
- budget失败返回部分树，path/length/indices为null；invalid_start/goal也返回明确状态。
- seed固定随机输入；如果time budget提前触发，硬件/负载不同会改变停止点，不能保证同seed树相同。
- 每条树边在插入前检查，parent只能指向较早节点，root parent=−1，因此回溯无环。
- `exact_segment_clearance`只用于搜索后评分，绝不用于选节点或纠正树。
  `status=success`表示**采样检查器**找到路径，后验`path_recheck.exact_valid`独立报告。
  CLI只有搜索成功且本课解析评分通过才exit0；预算失败或解析发现碰撞exit1，非法参数exit2。

## Explanation → Failure Cases

RRT探索绕开了直连障碍；两seed的随机探索产生不同树和首条路径，长短变化不代表某seed普遍更好。
普通RRT不是RRT*，本课没有rewiring或最优性保证。

- **扩展点安全、边不安全**：必须调用S14.2 edge checker，不能只检查candidate。
- **粗分辨率污染树**：独立实验edge_step=.4时初始直连被误接受，planner status成功，
  解析clearance仍为−45 mm。RRT不能修复碰撞oracle的漏检；CLI后验评分会以exit1暴露。
- **goal bias过高**：p=1不探索随机方向，可一直撞同一障碍而耗尽attempts。
- **节点预算不限制失败尝试**：树增长不了也能不断尝试，所以还需要attempt/time预算。
- **最后连线未查**：靠近goal不代表到goal的完整连接合法。
- **近零方向**：避免除零/重复节点；parent必须复制正确nearest index。
- **错误成功输出**：预算失败不能给出“接近goal”的伪完整path。
- **理论边界**：常见理想条件下RRT讨论概率完备性；有限预算、离散碰撞检查、p=1与实现限制
  不能据此声称本课对任意场景必定找到真实可行路径。参见[LaValle教材章节](https://lavalle.pl/planning/node230.html)。

## Robotics Context → Interview Capsule

配置空间树可用于多关节机械臂避障；真实接入需要保持metric/steer/joint topology一致，
使用完整robot/environment/held-object碰撞模型。本课只学搜索逻辑，UR5e接入留到S14.7。

**30秒**：我实现single-tree RRT，随机采样加goal bias，线性nearest查询，限长steer，
整段碰撞检查后追加parent，靠近goal时再检查末段，最终回溯首条路径。
失败明确预算状态；seed用于复现，采样安全与连续安全分别报告。

**2分钟**：RRT维护root到所有节点的已检查连接。每轮取目标并向最近节点扩展η以内，
边按h采样，失败不插入；接受后parent指向nearest。目标在η内时检查末段才宣布成功。
沿parent回到root并逆序重建路径。η控制树增长，h控制碰撞分辨率，不能混用。
节点/尝试/合作式时间预算分别防止内存增长、碰撞停滞和耗时失控。首条路径非最优，
预算失败非无解；同seed复现依赖time预算不截断。独立解析scorer验证本课圆盘场景，
不影响搜索，也不推广为真实机械臂连续安全或动态可执行结论。
